# Syntax Summit — do not submit this repo

The public listing is a domain-specific language hackathon, not a DevOps challenge. This case study should not be entered as if it were one.

## What I could and could not read

`https://devpost.com/submit-to/30764-syntax-summit` and `https://syntax-summit.devpost.com/` both returned HTTP 403 to curl from this machine, so the HTML was not read directly. Web search snippets of those public pages, retrieved on 1 Oct 2026, are the source of the points below. Confirm them in a browser before you rely on the dates.

## Theme

Syntax Summit ("Invent. Compile. Inspire.") asks you to design and build a domain-specific language: a parser, interpreter, transpiler, or compiler, documentation of the syntax, sample programs, and a video of up to 5 minutes. Suggested domains include AI, robotics, finance, healthcare, education, cybersecurity, games, automation, and IoT.

This repository is a DevOps case study: Flask services, GitHub Actions, Ansible, Kubernetes rollouts, and Prometheus. It does not implement a language. Forcing it into that theme would be a mismatch, so there is no filled-in submission and nothing was submitted.

## Deadline and eligibility, from the snippets

The snippets disagree, which is why you should look at the page yourself:

- The schedule snippet says submissions run from 19 July (PKT) through 14 January 2027, 5:00pm PKT, with judging 15–19 January 2027.
- A rules snippet still says the deadline was 5 September 2026, 5:00pm PKT. That date is already past as of 1 October 2026.

Eligibility snippets: at least 16 years old, students, teams of 1–4, companies excluded, projects created during the hackathon period.

## Judging, from the snippets

Innovation and originality, technical implementation of the parser or compiler, language design, documentation, real-world impact, and a small score for developer experience. A point split seen in one snippet was 25 / 25 / 20 / 10 / 15 / 5.

## If you build a real DSL later

The form will want a title, a short tagline, inspiration, what it does, how you built it, challenges, accomplishments, what you learned, what's next, built-with tags, a repo link, and a demo video. Those fields should describe the language, not this case study. Assets you would produce yourself: a cover image, screenshots of the language running, and the video. I will not submit it.
